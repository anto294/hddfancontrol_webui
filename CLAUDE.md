# CLAUDE.md

Web UI and process supervisor for [hddfancontrol](https://github.com/desbma/hddfancontrol) 2.x and [hd-idle](https://github.com/adelolmo/hd-idle). Repository: `anto294/hddfancontrol_webui`. For any Linux host (TrueNAS SCALE, Proxmox VE, Unraid, OpenMediaVault, any distribution with systemd), on x86_64 and arm64: shipped as a Docker image (`ghcr.io/anto294/hddfancontrol_webui`, a description per tag set by `docker.yml`) and as bare metal tarballs (systemd). Nothing may require one system; what is specific to one is a note in the README. All code lives in `hddfancontrol_webui/`.

## Architecture

- **Privilege separation** (never weaken it): the process the network reaches is never root. `__main__.py` is the **core** (root): it builds everything from the environment, serves the core API (`web.py`) on a Unix socket only (`web.UnixSite`, folder 0710 and socket 0660 for the gateway's group, `privsep.py`), runs with umask 077 (and `tighten_config` closes older files of `/config` at start, not `web/` or `web-tls/`), and starts the **gateway** (`gateway.py`) as `WEBUI_USER` (default `hddfancontrol-webui`, created by the Dockerfile and install.sh; the current user when not root; as root, a missing user, root or root's group give `None`: no gateway, the core alone drives the fans, never `nobody`) through a `Daemon` with `user=` (no extra groups, umask 077, `stdin=DEVNULL`, `start_new_session=True`), a filtered `env=` (`privsep.GATEWAY_ENV`, `HOME=/nonexistent`, no `PYTHONPATH`) and `python -I` (`gateway_command`: the package root is passed as an argument). `prepare_web_dir` first closes a `/config` the gateway could write (`_close_config`: chown root, no g/o write, the sticky bit does not count; when it cannot, `prepare_web_dir` gives `None`: no gateway, like a missing user; any other failure gives a temporary folder), then gives the gateway `/config/web` (credentials, self-signed TLS; older `/config/auth.json` and `/config/tls` are moved there) and the search bit on `/config`; root never writes or follows anything inside that folder (a gateway taken over could plant links). `given_tls` copies `TLS_CERT`/`TLS_KEY` to root's `/config/web-tls` (group-readable): only PEM files on a path the gateway cannot change (no part its own, no folder its group or everyone may write without the sticky bit); a half, unreadable or refused pair is passed as given so the gateway reports it. `serve`: an `AppRunner`, SIGTERM/SIGINT set an event; `Supervisor.release_fans()` gives the fans back first (cancels a PWM test, ends manual control, `fans.stop(final=True)`, then `closing`: nothing starts, changes answer `Busy`), then the gateway stops and `runner.cleanup()` runs the lifecycle, which stops the daemons. At start, in the background: sensor module scan (unless `LOAD_SENSOR_MODULES=false`), then `Supervisor.start()`, then `Monitor.start()`.
- **`gateway.py`** (unprivileged): middlewares `network_filter` (`WEBUI_ALLOW`, private networks by default, loopback always; others get a bare 403, logged once an hour), `host_check` (`Host` must be an IP, `localhost`, a dotless name, a `LOCAL_SUFFIXES` name or one of `WEBUI_HOSTS`, else a bare 403 logged once an hour per name; 400 without a valid `Host`; `/healthz` always; all "Refused" lines together at most `REFUSED_LOG_MAX` an hour, then counted (`RefusalLog`)), `security_headers` (strict CSP, COOP/CORP, Permissions-Policy; `Server` without version), `https_only`, `authentication` (public: `PUBLIC_PATHS`; without credentials only the setup: pages go to `/login`, the API gets 401 `setup_required`; `LoginLimiter`, 429 after 10 failures in 15 min per address (IPv4-mapped counts as IPv4), also for setup codes; one check under way per address; an IPv6 /64 past 10 failures only slows its addresses down (`delay`), never a refusal; past 100 failures from all clients, the checks of clients that failed wait a growing delay, one at a time, never a refusal), `csrf` (non-GET needs `X-Requested-With: fetch` and a matching `Origin`; `/api/*` and `/metrics` refuse `Sec-Fetch-Site` same-site or cross-site, GETs too). Its own endpoints (`GATEWAY_API`): login, logout, `/api/setup` (the `SetupCode` printed in the log at start, 64 bits, ends once used), `/api/auth` (GET; PUT with a session; credentials can never be removed). Everything else under `/api/` and `/metrics` goes to the core through `forward`, which builds the core's headers from scratch: `FORWARD_HEADERS` plus `HEADER_USER`, `HEADER_CLIENT` (const.py), so a client cannot forge them. `build(env, log)` reads its environment; `/healthz` asks the core's.
- **`settings.py`**: the `Settings` dataclass, `from_dict` (the only validation; collects every problem as `{field, code, params}`, codes translated as `error.<code>`), `env_document` (environment variables → document; without `MONITOR_DRIVES`, `monitor_drives` defaults to the `/dev` paths of `drives`), `hddfancontrol_args` / `hdidle_args` (command lines), `SettingsStore` (`settings.json` wins over the environment; a bad file falls back to the environment and sets `error`). `notify_url` leaves the core only as `masked_dict()` (`mask_notify_url`: user/password, query values, fragment, ntfy topic become `NOTIFY_MASK`); `put_settings` runs `restore_notify_url` first (the mask sent back keeps the address, a broken mask is `notify_url_masked`). Every value that reaches a command line or a path goes through here: drives are `/dev/disk/by-id|by-path/…`, `/dev/sdX` or `/dev/nvmeNnN` (`is_drive_path`) or interface names, PWM files are `/sys/class/hwmon/hwmonN/pwmN` (`is_pwm_path`), hwmon inputs `/sys/.../tempN_input` (`is_temp_input`), chips under `/sys/devices/`, no `..`; every pattern is matched with `fullmatch` (or ends in `\Z`), never `^…$` with `match`.
- **`supervisor.py`**: `Daemon` runs one program and restarts it with a growing delay (5 s doubling to 60 s, reset after 60 s of running); stop sends SIGTERM, then SIGKILL after `STOP_TIMEOUT`. Its `on_exit` hook tells the fan controller that hddfancontrol stopped (`_measuring_lost` → `FanController.measuring_lost`: full speed until a newer sample); `_stop_daemons` stops the daemons first and restores the fans last. `Supervisor` owns hddfancontrol, hd-idle, the `FanController`, manual mode and the PWM test, behind one `asyncio.Lock`; changes are refused with `Busy` during a PWM test. Manual control ends by itself after `MANUAL_IDLE_TIMEOUT` (120 s) without `touch_manual()`, which `GET /api/status` (polled by every open page, also from a background tab while manual control is on) and `set_pwm` call. With `read_only` (from `Hardware.read_only()`: `/sys` mounted read only, as in a container that is not privileged) nothing starts, mode is `read_only`, and manual control and the PWM test raise `ReadOnly`. During a PWM test hddfancontrol keeps measuring (`measure_only`) and `_watch_test` cancels the test on a drive at its maximum or stale temperatures (`FanController.watch_drives`, the checks of manual control; `test.stopped_by`); each output is cut at `PWM_TEST_MAX_S`. In manual mode `set_pwm` takes any PWM output of the host (to find out which fan it drives); the curve and auto modes write only `settings.pwms`. `LogBuffer` keeps the last lines and echoes them to stdout as `[source] text` from a thread of its own (queue of `ECHO_QUEUE`, dropped when full; `close()` at exit): `add()` never blocks nor raises.
- **Modes**: hddfancontrol always runs with `--fan-cmd /bin/true`, so it only probes the drives (without waking them) and writes `--temp-log`; `fancontrol.py` writes the PWM files in the `curve` and `auto` modes and in manual control. Manual mode is never saved. Its `--average` has no effect there: `DriveTemps` averages `settings.average` samples itself.
- **`fancontrol.py`**: `PwmWriter` saves `pwmN_enable` and the value the first time it writes an output (also in `/config/pwm-state.json` with the boot id, so a run after a SIGKILL of the same boot takes the chip's state, not its own leftovers; an entry ends when its output is given back; only `is_pwm_path` entries with numbers 0-255 are read back, and `_give_back` checks the path again), sets enable to 1, and `restore()` puts the mode back (an output found in manual mode gets 255). It writes only `is_pwm_path` files and saves an output only once its mode is written. `PiController` (KP, KI, at most -10 % per step; `step_error` takes the error over the target and whether a drive is at its maximum). `FanController` runs the control loop (`_control_step`: per fan, the drives it follows from `Pwm.drives` via `drive_names` = `Hardware.kernel_names`, or every drive; limits from `Settings.limits_of`; curve with `CURVE_COOLDOWN` and at most -10 % per step, or one PI per fan on the largest error) or the manual safety loop. Safety rules that must never be weakened: a drive at its maximum (its last reading, `DriveTemps.raw`, never the average), or at `drive_ceiling` (`DRIVE_CEILING` 65 °C, `NVME_CEILING` 80 °C, whatever the settings; the hot alert uses it too) → its fans at 255 (manual: every fan; a drive outside every fan group belongs to every fan); no sample newer than `max(3 × interval, 120 s)` → full speed (auto mode; manual mode too when drives are set, with `safety_reason` "stale"); an unexpected error in the auto or manual loop → every fan at 255 (written before anything is logged; `_log` swallows a failing log) and `error` in the status, and the loop goes on; `stop()` restores in a `finally` around the cancel; `stop()` always restores, except at the final stop (`final=True`, the web UI exits) with `restore_fan_settings` off.
- **`templog.py`**: reads only the last line of hddfancontrol's JSONL temp log, when its size or mtime changed, and keeps the last sample across the daily rotation. `fence()` (called by the supervisor before each start of hddfancontrol, `fence_samples`) hides the samples of the run before: the split drives/sensors depends on the settings. hddfancontrol logs every drive first (an interface name such as `ata` gives one entry per drive), then every hwmon input, which is never missing: `_drive_temps` takes every value but the last `len(hwmons)`. hddfancontrol logs null for a sleeping drive and for a failed probe alike (it tolerates 4 in a row), so `DriveTemps` keeps a drive's last temperature for `NULL_HOLD_INTERVALS` intervals of sample time.
- **`hardware.py`**: reads `/dev/disk/by-id` and `/sys/class/hwmon` (and `/sys/class/block`, with the I/O counters of its `stat`; `/proc/stat` and `/proc/loadavg` for `cpu()`, whose temperature is the package input of `_CPU_CHIPS`). Returns real `/sys/...` paths even when tests read a fake tree. Never sends a command to a drive. The snapshot carries counters, not rates, and a monotonic `clock`: the page (`updateRates` in `app.js`) turns two snapshots into rates, so the server keeps no state per client. `report()` gives the host as the hardware support request asks for it (`.github/ISSUE_TEMPLATE/hardware_support.yml`, the same lines as its shell block): the DMI fields named in `_REPORT_DMI` only, never a `*_serial` or `product_uuid`.
- **`history.py`**: SQLite (`/config/history.db`, WAL) with `series(kind, name)` and `samples(series, ts, value)`; `query` averages into at most `HISTORY_MAX_POINTS` buckets per series. Also keeps the last SMART summary per drive and the notes on alerts. It cleans itself: `purge` drops old samples and empty series, `forget_smart` the SMART data of drives no longer monitored (both hourly from the monitor). Blocking: call it with `asyncio.to_thread`.
- **`monitor.py`**: records the newest temperature sample (once per sample, each drive under a stable by-id name, `wwn-` first, never under `sdX`) and PWM/RPM of every output every `RECORD_PERIOD`, logs a `[temps]` summary line (`summary`, on change or every `TEMPS_HEARTBEAT`), purges hourly, reads SMART of `settings.monitor_drives` (only those, and `Monitor.smart` shows only those) at the runs of `smart_schedule`; a reading asked by the page (`POST /api/smart`) and the page's sensor scan run in the background and answer 202 (they can outlast the gateway's `CORE_TIMEOUT_S`), followed through `smart_refreshing` and `sensors.state` in the status. A drive asleep at a SMART refresh keeps its previous data with `asleep: true`. Both loops log an error once and go on; the alerts are updated even when recording fails.
- **`alerts.py`** / **`notify.py`**: `Monitor.conditions()` returns what is wrong now as `{key: (kind, params)}` (hot drive with 2 °C hysteresis, on the readings held over a null like the fans' (`DriveTemps`, `NULL_HOLD_INTERVALS`), stalled fan, SMART failing/warning/unreadable, monitored drive gone from `/dev`, fan safety or control error, missing fan chips, fan wear from `Monitor.fan_wear`: RPM per PWM band against a baseline kept in `meta`, checked daily); `Alerts.update` logs (`[alerts]`, English) and sends each start and end to `notify_url` in `notify_language`, with the `alert.<kind>` texts of `static/i18n`. `notify.send` POSTs in ntfy, Gotify or JSON format, 10 s timeout, never to a `forbidden_ip` (loopback, link-local, unspecified, multicast, IPv4-mapped too; private networks allowed), checked on the connection's own resolution (`_GuardedResolver`) and in `from_dict` for literals (`notify_address_forbidden`), logs only host and port, and raises `NotifyError` with a `code`; a failed alert is logged, never raised. `Alerts` queues the messages (at most `QUEUE_SIZE`) for one sender task, so `update` never waits for the server; tests call `flush()`. Reminders (`notify_repeat_h`, not for alerts taken note of) and quiet hours (`in_quiet_hours`, local time; only `URGENT_KINDS` starts and reminders go out, the rest is held and sent as one message) live there too; `Monitor._send_summary` sends the summary at the runs of `notify_summary`, recording the last one in the `meta` table of history.db (never sent at the first look). `Alerts.ack` keeps notes in the `alert_notes` table of `history.db` as key → signature (params without `temp`/`percent`; SMART params carry the error counts), so an alert taken note of shows again when it gets worse; notes end with their alert.
- **`drivedb.py`**: `lookup(model)` gives brand, product line, use and recording (CMR/SMR) from model-number patterns. Add only lines whose numbers are unambiguous; never write temperature limits here (the drive reports its own through `-l scttemp`).
- **`smart.py`**: `smartctl -j -a -l scttemp -n standby`, reduced by `summarize` to the fields the UI shows plus the attribute table. `_selftest` reads the newest self-test (ATA or NVMe log); `start_selftest` runs `smartctl -n standby -t short|long`. `Monitor.run_selftests` (every minute from the SMART loop) starts the due ones (by `selftest_short`/`selftest_long`, for `SELFTEST_GRACE` after a run), keeping the times in the `meta` table. Warnings are codes translated as `smart.warn.<code>`.
- **`sensors.py`**: runs `sensors-detect --auto`, takes only well-formed `modprobe <name>` lines of the "Chip drivers" section, skips modules present in `/sys/module`, runs `modprobe` without a shell. Failures are reported in `SensorReport` and shown in the UI with the TrueNAS Init Script steps.
- **`auth.py`** (the gateway's): credentials from `WEBUI_USERNAME`/`WEBUI_PASSWORD` (win, read only) or `/config/web/auth.json` (scrypt, mode 0600). In-memory sessions: 7 days, or 12 hours without a request (`SESSION_IDLE`), at most `MAX_SESSIONS`. Changing stored credentials needs the current password and ends every session (`set_credentials` runs in a thread and leaves the sessions alone; the handler calls `end_all_sessions()` on the event loop after it); there is no way to remove them.
- **`aio.py`**: `cancel_and_wait(task)` cancels a task and waits for it; the task's own cancellation is swallowed, its error and a cancellation of the caller are not. Use it instead of `with suppress(CancelledError): await task`.
- **`storage.py`**: `write_atomic` writes every file of `/config` (settings, labels, auth) with mode 0600 to a new temporary file (`mkstemp`, random name, removed on failure), fsyncs it, renames it and fsyncs the folder, so a power cut never leaves an empty file. Blocking.
- **Fan chips**: `Pwm.chip` is the `/sys/devices/...` path of the chip (`Hardware.chip_of`). `Supervisor._placed` runs at start, apply and reset: it records the chip, finds the file again with `Hardware.locate` when the hwmon number changed (saving the settings and moving the label), and lists fans whose chip is gone in `missing_pwms`: only those are not controlled (the others are, and hddfancontrol measures whenever drives are set). While the list is not empty, `recheck_fans` looks again every `PLACE_PERIOD` and after a sensor scan of the page, and restarts when a chip is back. `apply` drops a `chip` sent through the API: the host's counts.
- **`cron.py`**: every schedule of the settings (`smart_schedule`, `selftest_short`, `selftest_long`, `notify_summary`, `notify_quiet`) is a five-field cron expression in local time, empty for never. `parse` (cached) raises `CronError` with a code and params like the settings problems; `Cron.matches/next/previous`, and `windows` for the quiet hours preview. `GET /api/cron?expr=` gives the next runs as the server's wall clock for the preview under each field. No dependency (Alpine has no croniter).
- **`tls.py`**: `ENABLE_TLS` (default true) → `ssl_context` (`TLS_CERT`/`TLS_KEY`, or a self-signed pair made once in `/config/web/tls` by the `openssl` program; it runs in the gateway). `DualListener` accepts on `WEBUI_PORT` (also with TLS off: then everything is plain HTTP), closes at once an address its `admit` refuses (`gateway.admit_address`: `WEBUI_ALLOW`) and connections past `MAX_CONNECTIONS_PER_ADDRESS`/`MAX_CONNECTIONS`, and peeks the first byte of each connection: `0x16` (TLS handshake) goes to aiohttp's server over TLS, anything else as plain HTTP; `_Counted` wraps the server's protocol to give the place back at close and drop a first request not complete within `REQUEST_TIMEOUT_S`. `FORCE_HTTPS` is the `https_only` middleware of `gateway.py`: over plain HTTP only `HTTP_PATHS` are served (`/healthz`, the `https.html` page's script and style); a page gets `static/https.html`, whose `https.js` moves the browser to HTTPS from its own `location` (never build a redirect from the Host header: CodeQL url-redirection); the API, `/metrics` and non-GET answer 403 `https_required`. Never HSTS, which would lock users out of a self-signed certificate. A certificate that fails leaves HTTPS and the redirect off, with an error in the log: the fans come first.
- **`bays.py`**: the bay map in `/config/bays.json` (`{rows, cols, slots}`, slots row by row, each a `/dev` path or empty, `check_bays`); `GET/PUT /api/bays`. Like the labels, it never restarts anything.
- **`labels.py`**: names of drives (by `/dev/disk/by-id` path) and fans (by PWM path) in `/config/labels.json`. Never restarts anything.
- **`web.py`** (the core API, root, Unix socket only): `core_guard` refuses a peer (SO_PEERCRED) not in `peers` (gateway and root) and writes every non-GET request to the audit log (`[audit]`, user and client from the gateway's headers); the status has no login state: a page that loads is logged in (the Security tab reads `GET /api/auth`). No login, CSRF, static files or pages here: those are the gateway's. Errors are `{error: code, problems: [...]}` (`httputil.py`). `GET /metrics` (`get_metrics`) is the Prometheus text format, behind the gateway's login like the API. `GET /api/support` fills the hardware support request (fields named as the form's ids: `system`, `host`, `logs`); its log lines come only from `SUPPORT_SOURCES` (never the gateway's or the audit's) with addresses masked (`mask_addresses`) and `/dev/disk/by-id` names (serial numbers) turned into kernel names or `<drive>` (`mask_drives`). The page (`fans.js`) shows it all before opening GitHub, and cuts the link to `SUPPORT_MAX_URL`.
- **`static/`**: no build step and no external resources. `i18n.js` also holds the theme switch (`data-theme` on `<html>`, `localStorage` `theme`; style.css defines the dark colors for the system setting and for `data-theme="dark"`). `icons.js` holds the line icons, built as SVG nodes (`icon(name)`, or `data-icon` on an element); bars and charts are SVG with attributes, never style attributes (CSP). `wizard.js` is the guided setup: it builds a settings document from the answers and saves it through `PUT /api/settings` like the Settings tab; it opens by itself while the settings come from the environment with no drive and no fan, until it is closed once (`localStorage` `setupSkipped`). `app.js` holds the state, the helpers, the banners, the overview and the start; each tab has its own classic script (`fans.js` with the PWM test, `drives.js` for SMART, `history.js`, `settings.js`, `security.js` with the logs), loaded after it in `index.html` and sharing its globals. The page builds the DOM with `el()` and `textContent` only — never `innerHTML` with server data. Texts are flat keys in `static/i18n/<lang>.json` (en, it, es, fr, zh, hi, ar: `LANGUAGES` in `i18n.js`, `NOTIFY_LANGUAGES` in settings.py, the notify language options of index.html); a new key goes into every file, translated by meaning, not word for word; `tests/test_translations.py` fails if a key, a placeholder, a server error code or a status lacks a text, or a language is missing from one of those lists. Arabic turns the page right to left (`dir="rtl"`): use logical CSS properties (`margin-inline-start`, `text-align: start`...), never left/right, and pass a number with its unit through `ltr()` (app.js).

## Conventions

- One logical change per commit, with a detailed English message (summary, then what and why). Never batch unrelated changes. Run black before committing.
- `docs/` must always be well written and current: a change that alters behaviour, a safety rule, a default or a design choice updates its page (`docs/README.md` lists them) in the same commit, and a new choice gets an entry with its reason in `docs/decisions.md`. Quote numbers with the constant they come from.
- Format with **black** (line length 127, `pyproject.toml`). CI runs `black . --check`.
- Types: CI runs `mypy` strict (`setup.cfg`), with Python 3.11 as the target. A `type: ignore` needs a comment that says why.
- Lint: CI runs flake8 (errors only), and ruff with `E,F,B,ASYNC,S,I` on the package and `E,F,B,ASYNC,I` on the tests; a finding fails the job. Bandit and CodeQL run too. shellcheck checks `packaging/install.sh`, hadolint the Dockerfile, actionlint the workflows.
- Tests: pytest with `asyncio_mode = auto`; coverage must stay at 95 % or more. Tests use the fake `/sys` and `/dev` trees and fake programs of `tests/conftest.py`; never touch the real fans or drives.
- Every function and class gets a docstring, and top-level ones get this banner:
  ```python
  # ---------------------------
  #   function_name
  # ---------------------------
  ```
- Never block the event loop: file and SQLite work goes through `asyncio.to_thread`, programs through `asyncio.create_subprocess_exec` (never a shell).
- Keep the resource use low: no polling while the browser tab is hidden, no full reads of growing files, no new long-running process without a reason.
- The bare metal tarball carries its dependencies: `packaging/requirements.txt` (exact versions, sha256 of the `py3-none-any` wheels, aiohttp within `pyproject.toml`'s range) is downloaded by `release.yml` into `wheels/` and installed by `install.sh` with `--no-index --require-hashes`; the build tools are pinned the same way in `packaging/build-requirements.txt`. Update both with their hashes (Dependabot watches `/packaging`).
- Supported Python: 3.11 or later for bare metal (CI tests 3.11 and 3.14); the image uses Alpine's `python3` and `py3-aiohttp`. Do not add a dependency that Alpine does not package. Alpine 3.24's py3-aiohttp (3.13.5) is below the 3.14.4 of `pyproject.toml`: move the image to a release of Alpine that ships 3.14.4 or later as soon as there is one (the README, SECURITY.md and the changelog say so).
- The upstream versions are pinned in the Dockerfile (`HDDFANCONTROL_VERSION` with `HDDFANCONTROL_COMMIT`, `HDIDLE_VERSION` with `HDIDLE_COMMIT`, checked with `git rev-parse HEAD` after the clone; `SDPARM_VERSION` with its SHA-256), and the base images by digest (Dependabot updates them). `upstream.yml` opens an issue when a new release is out, with the commit of the tag; on an update, set the version and the commit together (`git ls-remote`, the dereferenced `^{}` commit for an annotated tag), check that `hddfancontrol_args` still matches its command line and that the `pwm-test` output still matches `_THRESHOLDS` in `supervisor.py`.
- `pyproject.toml` keeps `version = "0.0.0"`. The release workflow sets the real version for the wheel, and `docker.yml` passes the tag as `APP_VERSION`.
- Versions follow Semantic Versioning: a release with only fixes raises the patch number, one that adds a function or changes a default raises the minor number. Tags are `vX.Y.Z` or `vX.Y.ZbN` (the workflows reject anything else); publish a full GitHub release, not just a tag, and mark betas as pre-releases. Every user-facing change gets an entry under `## [Unreleased]` in `CHANGELOG.md` (Keep a Changelog); the release notes are that version's section, passed with `gh release create --notes-file`.
- The default branch is `main`. Features under test live on `experimental`: CI and CodeQL run on it like on `main`, and `docker.yml` publishes it as `:experimental` (`edge` comes only from `main`). `experimental` is `main` plus the hardware under test: merge `main` into it whenever `main` changes, never the other way until the user says a feature is confirmed; never rebase either branch.

## Development commands

```bash
pip install -e . pytest pytest-aiohttp pytest-asyncio pytest-cov black flake8 ruff mypy bandit
black .
ruff check hddfancontrol_webui --select E,F,B,ASYNC,S,I --ignore E501
mypy
python -m pytest --cov --cov-report=term-missing
docker build -t hddfancontrol_webui:dev .
```

To run the web UI without touching the fans: `CONFIG_DIR=/tmp/hfc LOAD_SENSOR_MODULES=false HDDFANCONTROL_BIN=<script> HDIDLE_BIN=<script> python -m hddfancontrol_webui`, with scripts that only sleep (or append fake samples to the `--temp-log` path they are given).
